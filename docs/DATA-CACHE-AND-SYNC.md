# 缓存、SQL 视图与局部更新

更新日期：2026-10-25。

## 页面行为

- 正常账号验证通过后，将处理后的业务查询结果缓存在内存和浏览器 IndexedDB 中，按账号、角色与账号版本隔离；退出或会话失效时清除。不缓存密码、认证结果、开发者密钥或写请求。
- 切换页面优先显示已有缓存。可见页面每 5 秒检查一次 `/api/data/revisions`；数据未变化时返回 304，不重新读取和计算业务数据。这是轮询同步，最长通常约一个检查周期，非即时推送。
- 每个查询记录所依赖资源的版本。设备、监测、工单、预警、库存等只有相关资源版本变化时才重新验证。数据库或数据集来源改变也会使缓存失效。
- 服务端保留有限的处理结果快照；有匹配基线且补丁更小时，仅发送 `fp-delta-v1` 补丁。新增、修改、删除均支持。基线不存在或补丁更大时安全回退完整响应。
- 前端不可变地应用补丁并复用未变化的对象，页面订阅对应查询；筛选和正在填写的表单不因后台检查重置。服务器计算过程中若数据再次改变，该结果不会被标记为可持久复用的版本。
- 网络异常保留已有显示并提示更新检查失败；认证仍必须由线上账号服务确认，缓存不能用于离线登录。

## 已在 Cloudflare D1 建立

`scripts/install-data-sync-views.py` 使用现有业务数据库配置执行一次原子、追加式迁移。2026-10-25 已执行并确认 24 台设备、34,560 条监测记录。

| 对象 | 用途 |
| --- | --- |
| `fp_resource_revisions` | 资源的单调版本；INSERT、实际 UPDATE、DELETE 触发器与业务事务一并提交，无变化 UPDATE 不增加版本 |
| `fp_v_record_counts` | 按记录类型统计数量，使用既有复合主键索引 |
| `fp_v_data_source` | 引用来源、数据集版本、设备数及监测数 |
| `fp_computed_freshness` | 记录预计算结果对应的输入版本 |
| `fp_v_processed_results` | 只提供当前数据集且输入版本仍匹配的预计算结果 |

SQL VIEW 本身不是物化缓存：复杂模型与质量计算继续使用已有 `fp_computed_views` 中的预计算结果；输入变化后失效。Python 内部监测缓存也包含记录资源版本，避免只按数据集名称缓存而漏掉同一数据集的记录修改。未能复用预计算结果时，正常业务计算路径仍有效。

前端实现：`src/data-cache.ts`、`src/useCachedData.tsx`、`src/api.ts`。服务端实现：`backend/data_sync.py`，在正常认证之后执行。当前启用范围为本地项目及其现有 D1 数据源；未发布新的线上 Workers 版本。
