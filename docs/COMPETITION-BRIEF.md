# FactoryPulse：面向生产约束的设备维护决策智能体

## 项目定位

面向制造企业设备主管与维修团队，将设备风险证据转化为受人员、备件、预算和生产窗口约束的维护安排，通过人工审批、执行与验收形成闭环。核心问题：先查哪台、依据是什么、何时能修、由谁执行、如何验收。

## 数据与效果证据

- **公开工业数据研究**：项目曾开展 MetroPT-3 等公开数据分析。本文件旧版保存过历史成绩，但相关输入和代码已经清理或变化，不能作为当前版本已重新验证的成绩。参赛引用前补齐来源与许可、数据摘要、预测目标、时间切分、基线、逐窗口或逐事件结果、代码提交及环境。
- **冻结软件验收数据**：24 台合成机床、34,560 条监测记录、144 次合成故障，用于软件行为、指标复算和流程检查。见 [验证集](MODEL-VALIDATION-DATASET.md)。不证明真实工业预测效果。
- **人员与现场效果**：任务用时、正确率、真实停机改善和经济收益尚无本文件可引用的完成证据。可先开展小规模模拟任务测试，无须等待工厂部署。

公开数据设备、字段和标签若与演示机床不同，分别报告预测实验与流程演练，不将两者拼接成真实机床效果。风险分数未校准时不称为故障概率；SHAP 不证明物理因果；优先级优化不等于经济收益最优。

## 部署与演示前置检查

当前架构包含 React/TypeScript、Workers/D1 和 Python/FastAPI 计算服务。完整能力取决于部署配置，以 README 为当前状态入口。历史 SQLite 部署、旧测试数量及旧输出路径不作为当前版本验收结论。

使用经部署者确认的专用演示环境和账号；D1 业务数据不能仅凭本地临时目录判断已隔离。写入前确认目标环境、备份及重置方式。核对数据版本、采样时间、演练资源日期、实际排程算法、模型服务和助手配置。

## 一次事件的演示顺序

| 步骤 | 操作 | 应展示的证据 |
| --- | --- | --- |
| 1 | 核对数据与资源 | 来源、版本、单位和模拟参数标记 |
| 2 | 复核设备风险 | 原始趋势、分数含义及模型限制 |
| 3 | Agent 查询人员、生产占用与库存 | 当前工具证据；缺参数时追问 |
| 4 | 生成需求与排程草案 | 动作、人员、时间及未安排原因 |
| 5 | 减少人员或备件后重新核对 | 冲突解释或新方案 |
| 6 | 人工批准、维修人员执行 | 权限与执行前重核 |
| 7 | 完工验收、查看履历 | 耗用、验收与关联记录 |

上述顺序不是已测得的用时成绩。备用录屏须明确标注，不冒充现场操作。

## 建议答辩表述

FactoryPulse 将设备风险证据与生产、人员、备件等约束连接起来，辅助形成维护安排，并保留人工审批及执行验收。当前冻结合成数据用于软件与流程验证；公开工业数据研究应另附可复查实验报告。我们分别评价预测效果、排程取舍和 Agent 任务表现，尚未证明的效率、停机改善和经济收益不列作已实现成果。
