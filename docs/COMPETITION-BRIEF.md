# FactoryPulse：设备风险与生产约束联动的维护决策工具

## 项目定位

面向制造企业设备总管，把设备监测、异常复核、维护需求、人员与生产排程、审批执行和维修履历连接起来。系统帮助回答四个问题：先检查哪台设备、依据是什么、什么时候可以修、由谁执行。

当前为本地部署验证版本。公开MetroPT-3数据用于历史模型验证；NASA IMS和合成机床数据为备用。MetroPT-3来自空气生产单元，不代表已取得制造企业机床现场效果。演示订单、维修人员、班次、预算和备件条件必须标为模拟。

## 业务价值与差异化

设备异常提醒只有进入可执行的维护流程才有管理价值。本项目将风险证据与技能、班次、设备停机窗口、生产占用、预算和备件联动，形成由人批准的安排。工单保留来源数据、维护需求、方案、审批及执行记录，处理后可以继续追踪。

当前已经验证软件流程与约束保护，尚未测量真实停机改善、劳动时间节约或企业经济收益。风险分数用于复核排序，不是已经校准的故障概率。

## 一次事件的完整演示

使用专用演示数据库或隔离副本。不得为了演示执行正在使用的业务库内工单。

|步骤|操作|应展示的结果|
|---|---|---|
|1|核对数据来源、字段、单位和覆盖时间|历史监测与模拟经营参数的边界|
|2|打开待复核提醒|设备、预测窗口和当前处理状态|
|3|查看设备工况、风险变化、故障与维修记录|原始采样时间及证据来源|
|4|查看解释、数据质量和模型限制|风险分数含义及适用范围|
|5|确认、驳回或延期|处理意见、复核时间与历史入口|
|6|创建维护需求|动作、技能、工时、备件及截止时间|
|7|核对排程资源|班次、预算、订单与设备窗口|
|8|比较方案并生成安排|人员与设备时间轴、成本及未解决冲突|
|9|设备总管批准或退回|硬约束冲突不能批准；批准依据留存|
|10|维修人员接单并开工|状态更新及执行前资源重核|
|11|暂停、恢复与完工|实际工时、费用及维修结果|
|12|设备总管验收或退回维修|验收决定、实际备件耗用|
|13|查看履历和审计|完整关联记录；后续风险变化不自动归因为维修收益|

这是一份演示顺序，不是已经测得的人员操作用时。五分钟完成复核至审批的目标仍需真实设备管理人员验证。

## 技术分工与可靠性

- React承载操作界面；FastAPI执行权限、状态和业务规则；SQLite保存业务数据、版本及审计。
- 风险算法处理时间序列与历史评估；CP-SAT在统一模型内选择任务、人员和时间，检查资源硬约束。
- AI负责理解问题、调用受控查询及解释证据。写入先形成草案，正式审批始终由人完成。
- 写入使用事务、版本校验和幂等回执；AI断连不妨碍人工业务流程。导入先校验预览、再明确确认提交，可取消并保留旧数据版本。
- 已完成174项后端回归及数据库副本中的14步Windows启停、软件网络屏蔽、业务闭环和重启持久化演练。测试通过只覆盖其实际场景，不等于生产可靠性认证。

## 建议答辩表述

FactoryPulse把设备风险证据转成受生产和维修资源约束的维护决策，并保留人工审批及执行追踪。我们已用公开真实运营数据完成时间外历史回放，也完成了隔离数据库中的维护闭环与重启演练。当前模型误报较多、独立故障样本少，因此坚持显示风险分数和证据限制；下一步需要实际设备管理人员试用及更多现场故障数据来验证操作效率和效果。
