# 严格评审修复与最终验收台账

本文件取代旧实验成绩作为当前验收入口。旧报告保留历史意义，其中被清理的数据路径不再作为当前可复算证据。

|评审问题|处理|验收界限|
|---|---|---|
|真实模型成绩差、单设备单事件、合成成绩外推|将唯一数据集冻结并校验摘要；统一定位为软件验证，撤下旧现场能力暗示|真实预测效果、跨工厂泛化仍需独立现场数据，未完成|
|评估分数与操作分数不一致|移除融合排序，模型存在时直接使用模型分数；工作台采用验证阈值|趋势或规则回退不继承模型成绩|
|首次提前量掩盖误报|增加合并提醒、无对应故障提醒、每设备每周负担、连续两条提醒确认提前量|提醒事件不是实际出勤，首次命中仍单独保留|
|仅按窗口F1选择、选择偏差|验证集提醒容量约束；预留隔离168小时后段稳定性检查，不用于选型|容量为情景设置，仍需真实人员测量；后段不足时标明不可评估|
|只读权限产生方案和库存写入|GET仅预览；POST受权限保护并保存方案；回归核对库存与方案表不变|分析缓存可能保存预测证据，不产生审批或方案|
|网页算法、收益、质量、排程、审批与本地不一致|停用旧浏览器伪API，公开页面改为同一数据的真实只读报告|完整业务使用本地后端；静态页不提供审批和导入|
|网页业务刷新丢失|移除只存在内存的网页业务状态；本地持久化继续由SQLite管理|静态页只有已发布报告|
|比较方案不可执行|POST默认三策略均做联合资源与时间校验，返回冲突；批准仍重核|缺少真实班次、订单等条件时保留情景假设；不等于现场许可|
|优化目标与收益宣传混用|明确最大化维护优先级总分；收益仅使用独立情景概率|没有实测经济收益，不宣称经济最优|
|弱基线|明确名称为编号顺序对照，不冒充企业周期维修策略|真实企业专家基线待现场提供|
|读取重训练、全量重复处理|按不可变数据版本缓存监测与模型；普通概览训练移出业务临界区；防轮询重入|冷训练仍需等待；本机耗时不等于长期并发负载认证|
|前端缺少实际页面证据|补本地和静态报告浏览器检查；功能分块加载，图表独立资源|具体浏览器结果见最新报告，不把构建当作页面验收|
|源码交付遗漏、依赖漂移|从已安装pnpm锁保存项目锁；后端保存精确版本闭包；交付包含配置和唯一数据|干净目标机安装仍待独立验证；不自动提交用户工作区|
|真实人员、收益和目标机为空|继续明确列出未验收门槛|不能通过代码或文档虚构完成|

最终验收数据：`data/model-validation/manifest.json`。计算报告：`outputs/final-acceptance/report.json`。浏览器DOM检查报告存于同目录。截图通道超时且备用浏览器工具未能启动，未宣称完成像素级视觉验收。历史文档中任何“默认MetroPT/NASA”等说明均已过期，以README及本台账为准。


新增发现与修复：分块构建后生成摘要过早，现改为读取最终落盘文件；重启后本地查询重复训练，现仅复用数据、训练配置与分析代码摘要完全匹配的持久预测证据。维护中心、工作台和助手采用同一模型复核标记，固定等级分段仅作展示。
