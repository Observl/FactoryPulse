# FactoryPulse 实施与验收记录

## 当前约束

- 沿用原有UI、侧栏和视觉风格；不采用先前计划的新设计。
- 页面优先显示关键数据和下一步操作。专业名词悬停或键盘聚焦可看释义，长说明默认收起。
- 优先完善项目，不进行网页或排版验证，除非排查具体bug。代码检查、后端测试和模拟传输单元测试继续执行。
- 用户满意度和比赛奖项必须由真实试用与评审证明，不以开发完成或测试通过代替。

## 已实施

- 七天标签排除已故障时刻和观察不足的尾部；缺少真实故障标签时不造标签。
- 训练、验证、测试按时间分开并隔离完整预测窗口；阈值仅由验证集选择。缺失指标保留缺失值。
- 评估包含同范围规则基线、独立故障事件、实际首次预警提前量与可追溯测试回放；不把风险分数当概率。
- 企业CSV/XLSX仅用表头与第二行辅助映射，确认指标与单位后后台逐批校验。支持进度、错误明细、预览、取消和原子提交，无人为文件大小上限。
- 导入不编造人员、订单和预算；未配置的维护参数不能用于排程。数据不足的设备单列“待评估”，不当作低风险。
- 数据版本归档和显式恢复；旧工单、预警与审计保留。维修事件独立持久保存，恢复来源版本后仍可追溯晚完成的旧工单。
- 设备检修条件、维修人员、班次、生产占用、预算和备件的录入与校验。资源修改后旧排程不能直接审批。
- 人工维护需求支持无模型证据的现场检查；只有已确认需求才能生成正式排程。
- CP-SAT检查预算、累计工时、团队人数、精确技能匹配、多人同时参与、班次、停机窗口、订单占用、同轮共享备件与已有工单时间占用。
- 正式排程与助手排程草案已将任务取舍、团队分配、时间、预算、累计工时及共享备件放入同一次CP-SAT求解，不再先按预算截断候选任务。三策略比较保留为对照；正式可执行安排以排程结果为准。
- 审批、接单、开工、暂停、恢复、完工、验收、退回修改和取消；版本冲突检查、幂等提交、事务审计。退回重提不沿用旧人员和时间。
- 智能助手使用白名单工具查询、解释、比较方案和起草维护需求。用户确认后才创建草稿，助手没有正式审批工具；无AI服务时可查询本地证据。
- 系统凭据保存失败会明确拒绝新密钥，不静默退回普通内存保存。
- 统一API错误提示、读取/提交超时与连接中断提示；写入失败不自动重试，提醒先核对是否已提交。
- 原有UI已恢复。新增内容使用原有面板和表单风格；流程、质量、评估口径、版本信息默认折叠，字段解释按需显示。

## 验证与限制

原始要求与现有证据逐项对应见`ACCEPTANCE-LEDGER.md`，区分代码、自动回归、隔离演练与真实现场验收；此台账不构成全部验收通过。

- 后端测试覆盖时间隔离、标签、字段与单位、导入事务、归档恢复、技能/班次/库存/订单约束、工单流转、数据版本隔离、AI草稿确认及凭据错误。
- 前端API单元检查使用模拟传输，不打开浏览器、不访问网络，覆盖字段错误、非JSON响应、写入中断、超时和重复提交保护。
- 这些检查只证明覆盖场景，不等于现场生产可靠性或用户满意度验收。
- MetroPT-3实际复算：1台设备、4个历史故障区间；隔离后的测试集6550个窗口、1次独立故障。精确率6.4%、召回率25.1%、误报率47.65%、F1为0.1021，首次预警提前167.17小时。该少量事件结果不足以证明泛化准确率，未经概率校准。

## 回答速度

常见、明确的设备排序和模型可靠性查询由 `agent_fast.py` 直接读取当前证据并生成纯文本答复，返回 `mode=evidence_direct`，不依赖第三方模型。复合请求、指定设备分析及写入草稿仍使用受控Agent，避免把复杂问题误判为固定问答。

Agent单轮缓存相同参数的设备、历史与评估读取结果，失败不缓存，草稿和排程计算不缓存。模型连接超时5秒、生成读取超时40秒，整体仍受60秒期限约束。此配置用于减少原20秒读取上限导致的过早失败，不代表外部模型一定在限定时间内完成。快速路径的证据读取在线程中执行，避免阻塞异步请求处理。

2026-10-20：快速路径、Agent及回答规范共32项测试通过。此结果验证常用查询不调用模型、数值与证据限制保留；尚未测量当前用户模型提供商的真实响应延迟。

复杂Agent响应新增 `timing`：总耗时、模型耗时、工具耗时、模型调用次数与同轮读取缓存命中次数；每项工具追踪另带 `duration_ms` 和 `cached`。这些字段用于定位慢请求，不记录密钥，也不以模拟测试耗时冒充实际模型延迟。33项Agent相关测试通过，其中重复相同读取的回归证明两次工具请求只执行一次本地查询。

后续速度优化：模型评估工具不再在读取评估前额外构建设备快照。重复命中的同轮只读工具结果向模型发送原始工具调用引用，首次完整证据保留在上下文，前端追踪和草稿数据不裁剪；工具JSON使用紧凑序列化。相关Agent测试34项通过，真实外部模型延迟仍未实测。

模型解释超时或达到分析上限时，响应标记 `completion_status=incomplete`，保留本轮成功读取的设备证据，前端可继续展示其原始数值和时间。未成功取证时不生成证据表，不将不完整回答标为已完成。相关Agent测试40项通过，包含解释阶段超时与首次调用超时两种模拟场景。
