## 部署前准备

可执行`python scripts/package-local-delivery.py --include-demo-data`生成白名单交付ZIP。它收录后端、已校验的本地界面构建、安装/启停/恢复演练脚本及必要文档，可明确选择带上MetroPT-3演示缓存；不打包当前业务数据库、密钥、日志、虚拟环境或试验副本。包内`delivery-manifest.json`记录每个收录文件的大小与摘要，`START-HERE.txt`说明能力边界。该ZIP不含Python和离线wheel，不能作为已完成验收的独立安装程序。

1. 在有网络的构建电脑准备项目支持的 Python、Node.js、Python依赖和前端依赖。
2. 完成前端生产构建，确认生成 `dist`。禁止将公开静态演示构建作为本地正式界面交付。
3. 将匹配目标Windows架构的运行环境、依赖、后端源码和 `dist` 一起交付。Python虚拟环境通常不能直接跨电脑搬运，应使用目标机安装或独立打包的运行环境。
4. 离线安装前准备所有依赖安装包，并在断网的隔离电脑完成安装与完整流程验收。AI在线接口不可用时，本地数据、维护工单与排程应仍可使用；离线不能承诺在线大模型问答能力。

## 离线安装入口

可先在已经通过测试的运行环境执行`python scripts/prepare-offline-requirements.py`，生成当前解释器的精确依赖闭包及运行版本、架构、源清单和锁定清单摘要。工具只读取安装元数据，不联网、不下载、不安装。包版本冲突或直接URL依赖会使生成失败。生成成功不证明所有版本都有匹配目标平台的wheel。

使用生成清单安装时增加`-RequirementsFile '实际目录\requirements-offline.txt'`。离线入口拒绝URL、嵌套清单和安装选项，只接受包名与版本约束；仍须从可信来源准备wheel，清单不是软件包签名，也不替代物理断网验收。

在准备电脑收集匹配目标Windows、64位Python及版本的全部wheel包，同时交付后端源码、生产构建`dist`和脚本。目标电脑需先安装64位Python 3.11或以上及其所需系统运行库；具体Python版本和依赖组合仍需目标机验收，不能仅凭版本号推定兼容。

在新的项目目录执行：

```powershell
powershell -File scripts/install-offline.ps1 -PythonExecutable 'C:\Python312\python.exe' -Wheelhouse 'D:\FactoryPulseWheels'
```

示例路径需替换为实际位置。脚本拒绝覆盖已有`.venv`，不启动应用、不迁移业务库；只从指定本地wheel目录安装，不查询软件源、不自动联网补齐。安装前核对本地界面构建模式，安装后执行依赖一致性和模块加载检查。离线包应来自可信准备电脑；脚本不提供软件包签名认证。

失败时保留新建环境与终端错误用于排查，不自动清理目录，也不把部分安装视为成功。创建环境前写入`.factorypulse-install-incomplete`标记，全部检查通过后才清除；存在标记时启动脚本和安装脚本均拒绝继续。不要手工删除标记来绕过失败，修正离线包后在新的项目目录安装。当前仅增加安装入口；尚未在干净电脑或物理断网环境完成完整安装验收。

## 启动已安装的服务

生产构建生成`dist/factorypulse-build.json`，记录本地/公开演示模式、文件大小和SHA-256摘要。启动脚本先校验该清单；公开演示构建、缺失或被修改的文件不能冒充本地服务界面。此检查不代表代码签名或网页验收。

执行 `powershell -File scripts/start-local.ps1`，或使用 `-Port 8010` 指定端口。脚本只监听本机回环地址，以一个服务提供已构建的界面和API，不需要前端开发服务器。默认数据目录为当前用户本地应用数据下的 `FactoryPulse/data`；可提前设置 `FACTORYPULSE_DATA_DIR` 使用指定目录。

脚本输出表示已经发起启动，不代替健康检查。查看该数据目录的日志，确认“Application startup complete”后打开输出地址。默认不会自动打开浏览器。

## 退出与重新启动

关闭页面不会自动停止后台。对本脚本启动的服务执行 `powershell -File scripts/stop-local.ps1`；自定义端口时增加同样的 `-Port` 参数，并沿用启动时的数据目录环境变量。停止脚本核对项目、进程启动时间与命令后，只停止记录的服务进程树。未知服务或身份不一致时明确拒绝，不会停止电脑上的所有Python进程。

停止前先确保没有正在提交的业务或生成中的备份。当前停止脚本通过结束进程退出，不代替优雅停机；未提交事务会回滚，后台任务可能需要重新发起。应用升级前先生成并核对备份，再停止服务，保存当前版本安装文件与配置。

## 正式交付门槛

本机隔离演练：`python scripts/verify-local-deployment.py --database <已完成演练的数据库副本>`。它再次复制数据库，使用Windows启动/停止脚本启动独立端口，通过Python网络入口屏蔽非回环DNS/TCP/UDP，验证AI连接失败时本地查询、方案比较、审批、执行与验收，并验证停止重启后的回执和工单状态。只访问API，不访问网页；源数据库不执行任务。

副本若启用账号，通过`--username`指定验证账号，密码仅放在`FACTORYPULSE_VERIFY_PASSWORD`环境变量中。副本清除旧会话，保留账号与权限。需有可创建需求的设备与足够资源；条件不足时失败，不绕过约束。

这仅验证本机现有环境，不代替干净电脑安装、操作系统防火墙、物理断网、界面或真实人员验收。输出副本含业务与账号数据，仅用于本机受控演练，不应公开上传。

数据库启动时记录结构版本与迁移基线，结构不完整或版本高于当前程序时拒绝启动。升级前仍需备份；该机制不支持随意降级，也不代表已有任意版本之间的升级脚本。

`/api/health` 仅供存活与基础数据库连接检查；启用账号后，`/api/health/ready` 需登录，可验证数据库写入权限及结构版本。就绪结果不证明备份可恢复、模型准确或生产现场可用。
