# FactoryPulse Agent Harness 使用与开发教程

## 1. 使用入口

启动方式见项目 README。使用独立账号登录，打开“设备运维助手”，展开“任务、会话与扩展工具”。

1. 填写任务，例如“复核 CNC-001，并核对明日上午的人员与订单占用”。
2. 填写成功标准，例如“引用当前数据，列出冲突；所有修改先申请授权”。这是任务验收说明，不是模型自行认证的业务结果。
3. 勾选需要的工具。首次发送后固定本会话工具集；改变工具范围须新建会话。服务器全局禁用优先于用户勾选。勾选不会提升账号权限。
4. 输入问题并发送。会话编号可复制到“恢复会话编号”，重新打开后恢复。会话只对创建账号可见。
5. 请求修改时，助手准备权限请求。核对字段差异、目标、理由和有效期，填写审批理由、勾选授权，然后点击“授权并执行这次变更”；也可拒绝。

权限请求十分钟有效，只允许原账号且当前角色为管理员/设备总管执行。授权绑定会话、原值、数据版本及服务器保存的摘要。任何资源版本变化都会要求重新申请。授权和业务写入在一次 SQLite 事务中提交，并同步生成审计记录。网页收到成功响应后刷新概览并清除旧方案比较结果。其他资源页面在重新进入时读取同一数据库。

当前支持修改已有设备的名称/类型、人员姓名/技能/可用工时/班次、订单生产时间、情景预算与约束。设备状态、传感器、PLC、账号权限、任意 SQL、删除记录和新建资源不属于该工具权限。正式工单仍使用现有“草稿确认→排程→审批→执行→验收”流程。

### 密钥保存与连接诊断

密钥优先保存到 Windows 凭据管理器；不可用时，使用 Windows DPAPI 在当前用户范围加密，原子保存到数据目录的 `credentials/ai-key.dpapi`。密文不进入业务数据库，普通数据库备份不包含该文件；其他 Windows 用户或其他电脑不能直接解密。两种安全存储均失败时返回错误，不保留新密钥，不回退到明文。

服务必须由具有正常登录配置的 Windows 用户启动；受限沙箱进程可能无法访问凭据会话或 DPAPI 用户密钥。使用项目启动脚本或在本机正常 PowerShell 中启动，不要通过复制数据库来迁移 API Key。重启后密钥会重新从安全存储读取。

保存后点击“测试连接”。未连接模型时，只有明确的本地快捷查询可回答，并标明“本地查询”；复杂问题会明确要求配置模型，不再用风险排序代替综合分析。默认最多8轮、4096输出token；时间预算从30秒开始，每次新的有效数据进展增加10秒。完成、失败或取消后，下一次请求重新从30秒开始。最终一轮优先收束分析，不再无限读取工具。运行层不再按金额预算拦截请求，模型服务商仍按实际用量计费。

## 2. 工具与 JSON Schema

登录后访问 `GET /api/copilot/harness`：查看启用工具、运行配置及请求/审批/资源的 JSON Schema。工具注册在 `backend/agent_registry.py`，Pydantic 生成模型可见参数，禁止工具参数额外字段；变更字段按资源白名单再次校验。模型不能注册可执行路径、SQL、shell 或任意 URL。

| 工具 | 功能 | 写入边界 |
| --- | --- | --- |
| equipment / history / evaluation | 设备证据、履历、模型评估 | 只读 |
| operations_context / work_order_flow | 分页资源及工单履历 | 只读 |
| compare_plans | 后端维护取舍计算 | 只读 |
| draft_work_order / draft_constraints / draft_schedule | 准备维护草稿 | 现有草稿确认与正式审批 |
| request_change | 准备具体资源差异 | 会话绑定权限请求，用户明确授权后才更新业务表 |

扩展工具步骤：在注册表添加参数模型和说明；在服务端添加确定性处理器；标记草稿/副作用；补齐权限、超时、失败、重复调用与数据版本测试；然后在新会话勾选。外部工具尚无任意插件动态安装功能，必须先完成服务端注册。不要把写入工具伪装为只读工具。

## 3. 会话、记忆与压缩

- 短期上下文：本轮模型消息、工具结果与缓存。所有查询重新校验当前业务版本。
- 会话记忆：SQLite `agent_sessions` 保存任务、成功标准、最近六轮问答；超过六轮，较早内容转为最多4000字符的明确标识历史摘要。摘要不充当当前证据。
- 长期记忆：用户点击“同意保存长期记忆”后，写入账号隔离的 `agent_memory`。最多50条，每条1000字符；最近10条进入模型上下文。可在界面删除。不会自动保存工具数据、密码或 API key；用户也不应在偏好中输入凭据。
- 模型上下文超过输入预算时按完整调用/返回对移除最旧的工具消息，保留任务、成功标准与最近证据；重复读取可从本轮缓存获得完整结果。不会通过摘要自动授予权限。
- `agent_runs` 持久保存 run ID、完成状态、工具 trace、时间和阶段时限。启动后的进程意外退出可能留下 running 状态，不能据此推断执行成功；批准结果以权限回执和审计记录为准。

数据库位于 `FACTORYPULSE_DATA_DIR` 下，复用现有备份机制。运行记录包含业务工具参数，不保存模型密钥、完整模型提示或隐藏推理。运维人员需按本企业保留策略管理数据库与备份；当前没有自动过期清理。

## 4. 阶段时限、失败与引用

编辑 `config/agent.json`，字段全部由 `AgentConfig` 校验：

```json
{
  "max_rounds": 8,
  "max_calls_per_round": 5,
  "max_tokens": 4096,
  "initial_timeout_seconds": 30,
  "progress_extension_seconds": 10,
  "tool_timeout_seconds": 15,
  "read_retries": 1,
  "max_input_tokens": 96000,
  "disabled_tools": []
}
```

每次运行初始截止时间为开始后30秒。每获得一次新的、有效且非空的只读业务证据，截止时间增加10秒，例如开始后20秒读到证据，时限从30秒变为40秒，剩余20秒；不会重置为“再给40秒”。空结果、错误、缓存复用、仅描述性消息、重复证据以及变更草稿不会增加时限。运行结束后返回的 `current_limit_seconds` 重置到30，`run_limit_seconds` 保留本轮累计时限供审计。超时、失败、取消和正常完成均不继承额度到下一次运行。

界面每两秒读取运行进展，显示当前时限和有效进展次数。模型等待受当前剩余时间约束；单个工具仍受 `tool_timeout_seconds` 约束。工具轮数和每轮调用数继续限制循环；超过每轮数量的请求留到下一轮，不把整项任务直接判为失败。旧版金额配置字段仅用于迁移兼容，不再执行金额拦截，也不再显示预留美元金额。

只读工具发生传输/连接类临时错误才按短退避有限重试；参数错误、权限失败、HTTP业务错误和副作用请求不自动重试。工具超时停止等待，不重试可能尚未结束的工作线程。取消网页等待不会强制终止 Python 线程，但模型工作线程只能查询或准备请求，不能授权业务变更。

模型上下文使用明确标注的证据视图：设备保留风险、工况和来源，省略界面已有的逐项评分公式；评估保留指标与限制，不展开全部逐事件表；维修时序保留首尾及风险/信号极值原始采样点，并列明原采样点数与摘要覆盖范围。完整工具结果仍留在运行缓存。模型若一整轮只重复读取已缓存证据，下一轮强制收束为最终分析，避免循环。

同一轮相同工具与规范化参数命中缓存，避免重复草稿。空 records/devices 明确标记为空；不是正常判断。每条成功证据带 EVID 编号，最终回答出现未知 EVID 引用会被拦截。该校验能阻止编造证据编号，不能证明自然语言中每个数字均正确；应结合证据区复核。外部链接不作为业务证据。

## 5. API 示例

所有 API 复用站点登录 cookie 与同源请求保护；未登录不能使用新 harness。不要把 cookie 放到日志或共享脚本中。

1. `POST /api/copilot/sessions`，请求：

```json
{"task":"核对设备命名与维护安排","success_criteria":"名称准确，变更有审批回执","tools":["equipment","operations_context","request_change"]}
```

2. `POST /api/copilot/sessions/{session_id}/chat`：`{"question":"查询CNC-001设备信息"}`。
3. 可由模型调用工具，也可 `POST /api/copilot/sessions/{session_id}/permissions` 准备具体请求：

```json
{"kind":"equipment","identifier":"CNC-001","values":{"equipment_name":"一号数控机床","equipment_type":"CNC"},"reason":"与现场铭牌一致"}
```

4. `GET /api/copilot/sessions/{session_id}` 返回会话、最近20个运行、权限请求和最近20条长期记忆。
5. 人工核对后 `POST /api/copilot/sessions/{session_id}/permissions/{permission_id}`：`{"decision":"approve","digest":"返回的64位摘要","reason":"已核对铭牌"}`；拒绝用 `reject`。模型没有该接口的工具定义。
6. 同一请求重复确认返回保存的执行回执，不重复修改。权限请求内容变化必须创建新请求；409 表示版本变化或过期，不能绕过。

## 6. 工业流程技能与 agent 组织

三个项目技能位于 `skills/`，由运行层加载到任务上下文：`risk-review`、`maintenance-planning`、`change-control`。分别借鉴 ISO 14224 的可靠性数据组织、ISA-95 的制造与业务信息交换边界、ISO 55001 的资产管理职责与改进思路。仅做工程流程映射，未完成条款级审计或认证。

- [ISO 14224:2016 官方范围说明](https://www.iso.org/standard/64076.html)：适用石油、石化和天然气行业；这里只借鉴设备与维护记录组织。
- [ISA-95 官方系列说明](https://www.isa.org/standards-and-publications/isa-standards/isa-95-standard)：业务计划与制造运行集成边界。
- [ISO TC251 关于 ISO 55001:2024 的说明](https://committee.iso.org/files/live/sites/tc251/files/guidance/ISO%20TC251%20ISO55001%20Rev3.pdf)：资产管理系统目标与要求概览。

当前采用单一 orchestrator + 三种专业技能，避免多个 agent 对同一资源争用写权限。当前未启用独立多 agent。未来确需多 agent 时，专业 agent 只提供带来源的只读建议；共享一个阶段性时间预算、截止时间与 permission gate，写入只由授权事务执行器负责。

会话运行互斥目前在单一服务进程内生效，部署时保持单 worker。多进程或多实例部署须先增加数据库运行租约和恢复机制；权限执行本身由 SQLite 事务和版本校验保护。

## 7. 验证与限制

```powershell
.venv\Scripts\python.exe -m pytest tests/test_agent_harness.py tests/test_agent_contracts.py tests/test_agent.py tests/test_agent_fast.py -q -p no:cacheprovider
npm run build
```

本地模型测试使用模拟响应，验证工具契约与权限边界，不代表已验证任意外部模型质量。`completion_status=complete` 表示编排正常结束，不表示用户的业务成功标准已被独立验证。对实际写入，以权限 `executed` 回执、数据库原值/新值与审计记录联合验收。
