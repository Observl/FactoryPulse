# 界面统一规范

沿用现有橙色工业风格与六入口布局。共享规则在 `src/ui-consistency.css`，加载于原样式和功能扩展之后；后续新增组件复用这些变量与控件，避免继续引入独立的颜色、间距和圆角。

- 白色面板、浅灰背景、克制边框；橙色突出主要操作与选中项。
- 页面标题26px，模块标题15px，表格与控件13px，辅助说明12px。移动端输入文字16px。
- 面板圆角10px，控件圆角7px，标准控件高度38px；状态同时使用文字与颜色。
- 页面顺序为标题、筛选、主体、操作结果。长说明默认收起，专业词使用可聚焦释义。
- 工作台以紧凑表格为主，筛选数值就近展示；完成条件放入状态释义，行尾保留具体处理入口。
- 加载不展示虚假零值；无设备提供数据入口，筛选无结果可一键清除条件。
- 不通过减小到难读字号隐藏内容。复杂表格在容器中横向滚动，主页面保持可用。
- 键盘焦点可见；尊重系统减少动态效果设置，不用装饰性动画干扰操作。

本轮仅执行代码与构建检查；依照用户约束，尚未进行网页和视觉排版验收。

## 说明与历史入口

- 帮助入口位于侧栏底部及移动端“更多”，集中承载13步操作指南、指标词典和数据备份说明。业务页不再重复展示完整教程。
- 风险中心的历史验证分为“评估结果”和“事件回放”；方法、版本及原始数量按需展开。
- 维护中心的预警处理记录支持设备、工单和处理意见搜索、状态筛选及每页10条分页。关联工单通过 source_alert_id 匹配，点击后切换工单筛选并定位至工单区。
- 提交成功与列表刷新失败分别反馈；已保存的工单操作不显示为提交失败，刷新成功后才能继续处理旧列表上的动作。

## 智能助手回答规范

回答规范由后端 `backend/agent_policy.py` 统一维护。助手仅服务于设备监测、风险、维修、排程、数据接入及系统相关操作；明显无关问题和显式绕过规则的请求在模型调用前拒绝。

模型应使用简体中文纯文本，最多四个短段落、900字，先结论后依据与下一步。输出经过常见Markdown、HTML和代码块清理。业务事实仍须来自受控工具，原始证据独立保留；无数据不得编造。系统提示与规则过滤能减少偏离，不能证明大模型在所有表达下均合规，仍需结合真实使用持续检验。
