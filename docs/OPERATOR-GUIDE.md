# FactoryPulse 操作手册

适用对象：设备总管、维修人员与管理员。当前版本为试用版本；风险评分不等于已校准的故障概率，情景收益不等于实际节省。

## 一、准备数据与账号

1. 管理员确认部署电脑、数据保存位置和备份责任人。
2. 在开发者设置的“账号与权限”中启用账号保护，设置首个管理员。多人使用时分别创建设备总管、维修人员或仅查看账号。维修人员账号需要关联已录入的人员编号。
3. 未启用账号保护时为本地单人模式，手填操作人姓名不能证明身份。不要把该模式的记录当成经过认证的多人审批记录。
   收到初始密码后，在账号旁点击“修改密码”，输入当前密码及两次新密码。保存后所有旧会话失效，使用新密码重新登录。
4. 确认当前数据来源。公开历史数据用于回放；模拟资源只用于演示，不能直接作为现场生产条件。
   页眉数据入口显示载入状态，不代表实时采集。最新采集时间来自监测记录，版本启用时间表示文件何时导入；页面定时刷新不会更新历史数据本身。

## 二、导入企业数据

1. 在设备总览选择 CSV 或 XLSX 文件。
2. 核对字段映射与单位。AI只读取表头及第二行辅助判断；自动匹配不是最终确认。
3. 明确设备编号和采集时间。没有可靠时间或真实故障标签时，不能声称完成未来七天故障预测验证。
4. 提交后台解析，查看进度、有效记录与错误明细。修正错误后重新导入；取消任务不会替换当前正式数据。
5. 预览设备数量、时间范围和指标，确认后启用数据版本。启用前仍使用旧版本。
6. 打开数据质量说明，核对缺失、重复、中断和数据新鲜度。版本恢复需要明确选择历史版本；不会恢复已经消耗的实物库存。

## 三、确认维护条件

1. 在维护计划的资源配置中选择设备，保存检修动作所需技能、人数、费用、工时和允许停机时间。
2. 录入维修人员技能、可用工时和班次。
3. 录入生产订单占用设备与时间、交期。当前系统不会自行调整生产订单顺序。
4. 在备件库存中确认实盘数量；已有备件的数量在库存页调整，不通过设备需求覆盖库存。
5. 保存本轮排程预算、同时使用人数和累计停机工时上限。累计工时为各台设备维修时间相加，并行维修也计入。
6. 未补齐的条件先补齐再排程。不得为通过校验随意填入零费用或不存在的人员。

## 四、处理预警或主动检查

设备详情为完整页面，可从工作台、设备台账或风险中心进入。页面包含工况、历史风险、维修履历、生产订单、维护工单和操作追溯；“返回来源页面”回到进入前的业务入口。地址中的设备参数可保留当前查看对象，切换数据版本后仍需核对设备身份。

1. 在风险预测或执行审批打开设备，查看最新数据时间、异常指标、风险变化和维修历史。
2. 证据不足时保留“待评估”；这不表示设备安全。风险分数只用于辅助排序，不解释为同等数值的故障概率。
3. 确认预警表示已复核，不代表已维修。驳回需记录理由；延期需填写下次复核时间。
4. 需要维修时创建维护需求。模型证据不足但现场需要检查时，可在设备检修条件下创建人工维护需求。
5. 在维护工单列表找到新需求，核对动作、设备与状态，再生成检修安排。
   工单默认显示未关闭任务，可按状态筛选或搜索工单、设备及人员。维修人员可选择只看分配给自己的任务。转需求、审批和执行操作后，列表会定位相关任务；查看其他任务时清除搜索即可。

## 五、排程与审批

1. 选择已保存的排程条件，生成检修安排。
2. 核对设备、人员、起止时间、备件和订单影响。无法安排时先处理系统列出的缺项或冲突，再重新生成。
3. 比较方案时区分真实约束与明确的模拟假设。导出的方案文件对应生成时的数据与条件，不代替后续审批。
4. 设备总管批准或驳回待审批工单。存在假设时先逐项核对；驳回需填写意见。
5. 数据版本或资源条件变化后，旧方案可能失效，应重新排程。批准不等于已经接单或开工。
6. 智能助手可起草条件调整或排程草案。条件调整需确认后另存；排程草案需核对人员、时间和冲突后确认进入待审批。确认不会跳过设备总管审批，条件或占用变化后需重新生成草案。

## 六、执行与验收

1. 被分配的维修人员登录后确认接单。
2. 实际开始维修时点击开始维修。需要暂停时填写原因；具备继续条件后恢复。
3. 提交完工时填写维修结果、实际工时与实际费用。提交完工后进入待验收，不立即记为维修闭环完成。
4. 设备总管核对维修结果和实际备件耗用；未用的备件明确填写零。
5. 验收通过后保存维修记录，扣减实际耗用并释放剩余预留。结果不合格则退回维修。
6. 取消已开始的维修时也需核对实际耗用，不能通过取消抹去已使用备件。
7. 在设备详情查看维修历史，在工单查看处理过程；需要判断改善时结合维修前后工况与后续运行记录。
8. 跨工单复盘时，在执行审批底部展开“操作追溯”，按操作类型和设备或工单编号查询。点击“加载更早记录”继续查看历史；修改筛选后点击查询生效。系统记录只证明已保存的操作，不替代现场维修事实或防篡改审计。

## 七、异常操作

- 审批结果返回时断线：保留原审批内容重试，系统可找回同一操作编号的已保存结果，不重复批准、预留库存或写审计。随后刷新工单查看当前状态。原回执只证明当次审批结果，不会把后来撤回或重新排程的工单恢复成已批准。
- 旧审批页面：审批必须携带读取时的工单版本；内容或版本改变后，请重新打开并核对，不可沿用原操作编号提交不同意见。

- 审批后条件变化：接单和首次开工会再次核对数据版本、审批资源版本、正式设备/人员占用与库存。提示资源已变化时，由设备总管撤回待排程，核对资源、重新生成并审批；不要反复点击开工。
- 旧批准工单：缺少审批资源版本的旧记录需先撤回重排，不能直接开工。已经开工的维修事实仍可继续记录和验收，原数据来源保留。
- 核对依据：在工单内展开“执行前核对”查看时间及检查范围。校验基于批准的计划时间，不替代现场开工许可或对实际时点的安全检查。

- 提交超时或断网：先重新读取工单状态与处理记录，确认是否已成功，再决定是否重试。
- 提示版本冲突：刷新并核对最新条件，不能覆盖他人的处理结果。
- 会话失效：重新登录后核对当前状态再继续；共享电脑切换账号时不得沿用他人的待提交信息。
- 库存短缺：确认实盘及已有预留，补充或调整安排；不能直接批准超出可用库存的方案。
- 无可行排程：补充资源或调整允许窗口后重新生成；不把计算超时解释成已经证明无解。
- 操作按钮不可用：核对账号角色、工单状态和必填条件。仅查看账号不能修改资源或批准任务。
- 页面显示异常：记录恢复页的参考编号、时间与步骤，重新载入后先核对工单和处理记录，再决定是否重复提交。参考编号仅用于关联本次页面异常，不代表故障已经自动上报。
- 未保存提示：资源表单或工单操作表单修改后，离开页面前先保存或提交。系统不会把未保存表单长期存入浏览器；选择放弃后不能自动恢复输入。浏览器强制退出或断电仍可能丢失未提交内容。

## 试用验收

以真实设备总管完成一次“导入—复核—需求—排程—审批—接单—开工—完工—验收—历史查询”为验收任务，记录完成时间、卡点、错误与改进意见。实际满意度、停机改善和比赛结果需由试用与评审证明。
