# D1 事实表 V2：迁移与切换说明

日期：2026-10-25。

## 2026-10-26 迁移约束更新

按用户要求，不创建原库备份、不导出原库到文件，也不在库内保留旧表副本。下述独立目标库流程是早期设计，不作为此次线上迁移操作步骤。

此次采用原库同一事务完成转换、计数校验、兼容视图安装和旧存储清理。事务失败回滚；事务成功后使用 V2，不保留额外的 V1 备份。数据库 UUID 和账号库不变。`backend/database_v2_upgrade.py` 已实现此事务计划；目前本地针对性检查通过，不能据此视为线上迁移已经完成。

## 当前交付边界

新结构、转换器、隔离迁移工具及动态视图已经落盘。尚未连接线上执行，也未替换现有业务库。线上 V1 继续运行，账号库完全不改。

本次迁移工具是一次性构建独立目标库，不是 V1 应用的自动升级程序。它不会更新 Worker 绑定、业务配置、Dify database_id 或旧应用 SQL。

## 结构选择

- 每种基础业务对象有直接可读的表，不再将当前设备等混装在 records。
- 数量、库存可用量、最新采样、费用和时长在普通视图中计算。
- 原始人工总值与分项之和不同时保留人工覆盖，不能误删。
- 模型和优化算法在运行时计算，不伪造 SQL 实现；历史模型与方案证据仍可存档。
- 未知字段保留 attributes，不能自动认定无用后删除。
- 当前事实迁入新库，旧冻结副本、归档、导入和内部运行状态保留完整源导出；如需在线使用，必须在切换前追加专项适配。

## 1. 离线演练（不连接 Cloudflare）

在项目目录执行：

```powershell
.venv\Scripts\python.exe scripts/migrate-d1-business-v2.py
.venv\Scripts\python.exe -m pytest tests/test_database_v2.py -q -p no:cacheprovider
```

演练校验冻结文件 SHA-256，用独立内存 SQLite 验证 DDL、约束和转换，报告为 outputs/database-v2/report.json。它只验证通用 SQLite 语义，不代表已经在真实 D1 验证性能、配额或所有接口兼容性。

## 2. 源库只读导出及预检

连接配置沿用 account_id、database_id、token_file 结构，令牌保存在独立文件，不写入命令参数或指南。

```powershell
.venv\Scripts\python.exe scripts/migrate-d1-business-v2.py --source-config .secrets/business.json
```

此步骤只读取源业务库，以业务修订号前后比对检测常规应用写入。暂停导入、定时计算及包括 Dify 在内的直接 SQL 写入，安排维护窗口；绕过业务修订机制的直接写入无法单凭修订号检测。

原先自动生成源备份文件的行为已取消。此次迁移不运行本节的原库导出流程。

预检遇到未知 records 分类、缺失主键、非法时间、重复主键、重复备件需求或外键错误会停止；不会猜测修正、合并或丢弃业务行。

## 3. 构建独立的空 D1 目标库

先创建新的 D1，并将新 ID 写入私有目标配置，例如 .secrets/business-v2.json。源和目标必须使用不同 UUID；工具拒绝已有业务表的目标，不支持覆盖、DROP 或原地升级。

```powershell
.venv\Scripts\python.exe scripts/migrate-d1-business-v2.py --source-config .secrets/business.json --target-config .secrets/business-v2.json --apply
```

早期独立目标库流程：源导出 → 本地约束检查 → 空目标检查 → DDL → 分批导入 → 全字段读回比对 → database_schema 标记 ready。此次不采用该流程，也不创建私有源备份。

导入并非跨全部请求的单一事务。中途失败时独立目标可能包含部分数据，保持 building 状态，不得绑定到应用。工具不会自动删除该库；核对后另建空库重跑，源库始终保留。

源预检产生的 report 包括各表计数、每类删除字段数量、仅保存在备份的旧表和被排除的设置键。没有 migration_state=ready 的目标不能视为迁移成功。

## 4. 接入 Dify

新库完成真实 D1 验证后，查询 Agent 可单独接入目标库并导入新版 Agent SQL 指南。这提供的是迁移时点快照；现有站点仍写 V1 时，新库不会自动同步，不能宣称查询的是最新业务状态。

现有业务 Agent 继续查询 V1 时，应使用 AGENT-DATABASE-GUIDE-V1.md。新旧指南不要不加版本过滤地同时检索。

## 5. 应用切换前必须完成的适配

这些适配尚未在本次交付中实现，不能靠改一个绑定完成：

1. Workers 的 records 读写、资源和工单 SQL 切换到新事实表，保留用户权限、并发版本、幂等与原子写入保护。
2. Python 的记录接口、导入/恢复、事务适配层、模型训练/推理及排程数据访问切换。
3. 当前模型与历史查询不再依赖 fp_computed_views，改为实际计算服务；未接计算服务时明确不可用。
4. 对仍需要在线查询的历史数据集、导入作业与内置助手状态确定独立存储和迁移策略。
5. 真实 D1 中验证各视图延迟和扫描量，必要时调整索引，不用伪缓存冒充普通视图。
6. 对完整工单生命周期、库存预留/耗用、审批失效、越权和重复提交进行回归。
7. 停止旧库写入，重新导出并迁入最终空库，核对最终数据，统一切换所有读写方与 Dify。

## 6. 回退

切换前回退：继续使用原绑定与 V1 数据，无需改回源库。

切换并在 V2 产生新事实后：不能直接把绑定切回旧库，否则丢失新业务。先停止写入、导出新事实并完成反向映射和核对，再恢复旧实现。当前工具不提供自动反向迁移。

## 7. 不进入自动删除清单的内容

账号、密码、会话、用户权限、审批事实、正式验收、库存观测、操作幂等回执和并发保护不是为了简化表名就能删除的无用数据。新应用接入前必须保留其必要业务保证。
