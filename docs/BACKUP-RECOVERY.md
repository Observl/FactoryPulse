# 数据库备份与恢复

## 自动备份

后端默认在启动后生成一次快照，此后每24小时生成一次。默认目录为业务数据目录下的 `backups`。通过后端进程环境变量 `FACTORYPULSE_BACKUP_DIR` 指定其他目录；`FACTORYPULSE_AUTO_BACKUP=0` 关闭自动备份。`.env.example` 是配置示例，不会自动加载为后端环境变量。

备份使用 SQLite 一致性快照，并在发布文件前执行完整性检查。未完成文件以 `.partial` 结尾，不能用于恢复。备份包含账号密码散列、会话、工单、库存与审计等敏感数据，应限制目录访问权限，并定期复制到另一块磁盘或公司受控存储。默认不会自动删除历史备份，管理员需安排保留周期与空间监控。

管理员可在开发者设置展开“数据备份”，查看最近成功时间、文件及完整性校验结果，点击“立即备份”手动生成。面板每10秒刷新一次状态。接口为 `GET /api/backups/status` 和 `POST /api/backups/create`；没有备份文件下载接口。重启后会读取审计记录并确认文件仍在备份目录中；这不会重新校验文件全部内容。状态不等于恢复演练通过；没有成功记录时不能视为已有可用备份。

## 离线恢复步骤

1. 停止前后端，确认没有其他程序连接该业务数据库。
2. 另存当前完整数据目录，保留故障现场；不得直接删除原库。
3. 选定已完成的 `.sqlite3` 快照。使用数据库工具执行 `PRAGMA integrity_check`，结果必须为 `ok`；核对备份日期和业务范围。
4. 在临时目录打开备份副本，核对设备数、关键工单、库存及最新审计记录。不要先覆盖正式库再核对。
5. 将核对后的备份副本放入新的恢复数据目录并命名为 `factorypulse.sqlite3`。不复制旧库的 `-wal`、`-shm` 或日志文件到新目录。
6. 在恢复副本中执行 `DELETE FROM auth_sessions` 并提交，使快照内的旧登录会话失效。
7. 将 `FACTORYPULSE_DATA_DIR` 指向新的恢复目录，然后启动后端。应用版本需与备份兼容；不确定时先在隔离环境完成迁移与验证。
8. 管理员重新登录，核对关键工单、实际耗用、人员与订单，并补录快照生成后已在现场发生的业务事实。
9. 确认无误后恢复用户访问，记录恢复人、备份文件、恢复时间及数据损失时间范围。

数据库快照不包含原始上传文件、外部传感器文件和系统凭据存储。完整交付备份还需保存这些数据及必要配置；API密钥通过系统凭据重新配置。尚未完成恢复演练时，不得把备份功能称为已经验证的灾难恢复能力。

# 恢复验收补充

备份状态接口会核对最近快照文件是否存在、可访问且大小与生成记录一致；删除或截断后显示失败及重新备份提示，重启后仍保留该异常提示。此轻量检查不重新执行数据库完整性检查，不能发现大小不变的内容损坏；恢复前仍须执行完整性检查和隔离恢复演练。

恢复演练枚举全部持久业务表，排除已主动清除的登录会话和SQLite内部表；当前演练覆盖18类表。应用初始化前，恢复副本必须与备份摘要一致；初始化后仅允许未完成的导入任务转为中断，并保留任务编号和业务字段。缺失或损坏的暂存预览不能提交，需要重新上传。工单、配置、归档和规划资源等其他业务变化均使演练失败。
