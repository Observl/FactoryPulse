# 数据接入、字段与版本

## 当前支持范围

当前运行路径接收 CSV/XLSX；不直接接收 SQLite 数据库或 SQL 脚本，不将外部文件当作正在运行的业务库。已有数据库先导出监测表。历史 SQL 导入及旧数据集演练记录仅用于追溯，不代表当前入口支持。

## 导入流程

上传文件 → 选择设备方案 → 核对设备编号、时间、字段、单位与预测启用项 → 全文件分批校验 → 查看错误及预览 → 明确确认并启用数据版本。提交前继续使用旧版本；取消、失败或版本冲突不得发布部分结果。AI 仅接收表头与首条样例辅助映射，不把全文件交给模型。

CSV 可使用逗号、分号、制表符或竖线。时间支持日期时间、明确单位的 Unix 秒/毫秒；带时区时间统一为 UTC，无时区日期保持原值。预览时核对来源单位和时间，不能靠导入成功证明数据或预测有效。

取消、校验失败或无效的预览会在后台连接关闭后清理该任务的暂存数据库或 D1 暂存表；仍在校验的任务由工作线程结束后清理，避免与提交并发误删。原始上传文件和字段会话保留，供修改映射后重新预览；这不等于上传目录已全部回收。清理失败会记录服务日志，可重试取消。成功提交和仍可提交的预览不由取消清理逻辑删除。

## 字段与设备方案

可选通用、数控机床、旋转设备、压缩机、液压、热工、电气方案，同一文件可按设备覆盖方案与特征。推荐方案不等于已经验证的行业模型。

温度、振动、压力、流量、电流、电压、功率、转速等常见指标映射为标准字段；自定义数值测点保留名称及原单位，多测点分别保留。文本备注不能冒充传感器数值。实际故障标签用于构造未来窗口，未来结果不能作为预测特征。

## 质量、资源与来源

检查缺失、重复、采样间断、未来时间、数值异常和样本范围。证据不足显示待评估，缺失不补成正常或零风险。没有足够独立标签和时间外样本，不宣称已验证未来七天预测。

保存字段来源、单位、方案、特征与数据版本。人员、班次、订单、预算及库存需要独立录入，导入不会补造经营条件。设备占用时间轴区分生产与维护；取消或归档任务不产生有效占用，无起止时间不绘制伪造时间块。

当前业务使用 Cloudflare D1；仅隔离测试夹具可使用 SQLite。恢复历史数据版本不撤销已发生的维修和库存耗用。备份与灾难恢复见[部署与运维](CLOUD-DEPLOYMENT.md)，软件验证集见[模型验证数据](DATA-IMPORT.md)。

## 验证边界

已有字段、事务、取消、并发与恢复回归；极大文件、磁盘耗尽、长期负载和企业现场文件兼容性仍需专门验收。不把旧文档中的数据库文件容量限制套用于当前 CSV/XLSX 路径。

## 评分解释与排程方法

设备详情中的规则、近期变化、模型和检查优先评分卡片均可点击，打开计算方式窗口。

- 规则：显示真实数据来源、输入、阈值、系数、分项贡献及重新计算结果。外部工作簿未提供公式时明确标注不可复算。
- EWMA：显示实际选用指标、α、样本数、当前值、平滑值、历史残差基线和趋势分。未修改原评分公式。
- 模型：保存完整 SHAP 原始分贡献和基准值，验证 `sigmoid(基准 + 全部贡献)` 与模型实际输出一致，再与四位小数的展示分核对。前几项贡献不能单独用于复原。
- 最终分：模型可用时使用模型分，否则采用趋势分，再否则使用来源规则分；不进行加权融合。评分未经概率校准，不能解释成真实故障概率。

唯一冻结软件验收集逐设备检查规则、EWMA、模型复算。仍不能据此证明现场预测有效或因果关系。

## 比较性能

方案比较在一次请求内共享设备快照、人员、订单和工单数据；联合选择前不再执行结果会被丢弃的预算预选。同一请求中，候选任务与所有约束完全相同的排程复用一次求解结果，不跨请求复用陈旧业务状态。

本机同一冻结数据、固定起算时间的一次对照：约30.6秒降为20.1秒，三种策略的任务数、优先级总分、预算耗用与工时一致。报告生成于 `outputs/comparison-performance.json`，不代表并发负载或所有输入的性能上限。

## 最早可行安排

联合求解仍同时检查设备窗口、人员技能与班次、人员工时、生产占用、现有工单、库存、预算和累计工时。选择目标优先维护优先级总分，其次缩短总完成时间；可行解不冒充已证明最优解。

未指定起算时间时，从当前时间向上取整到分钟开始，不把任务安排在已经过去的整点。秒级可用窗口起点向上取整，占用结束向上取整、窗口结束向下取整，避免分钟离散化侵入生产时间。没有空档或资源不足时报告冲突，不移除约束来制造安排。

## 冻结合成软件验证集

以下为对应锚点及模型的历史软件检查结果，不代表现场预测效果。当前运行数据身份以 `data/model-validation/manifest.json` 为准；不沿用旧备用数据入口或把动态生成数据冒充冻结输入。

这是明确标注的模拟数据，目的是验证软件能计算完整指标；不代表真实设备准确率，不是概率校准证据。

## 数据内容

- 24台模拟数控机床，240天，每4小时采样，共34,560条监测记录。
- 144次外生故障，包含机械振动、电气负载和润滑热异常，以及维修恢复记录。
- 9项传感器指标；保留噪声、个体差异、正常高负载、突发故障与少量缺失。
- 维修参数、12名人员、24份订单、预算和模拟备件齐备，供需求—排程—审批流程演练。
- 随机种子20261021。指定相同日期锚点时，所有表可重复生成。内置载入以当天零点为锚点，监测截止前一天20:00，经营窗口安排在下一天；均为模拟时间。

故障发生时间预先独立采样，再生成不同类型的故障前工况。标签来自故障发生记录，不来自温度或振动规则阈值。未来168小时未完整观察到的尾部记录标为未知；已经故障的记录不参加未来故障分类。

## 模型与指标

训练、验证、测试按时间划分，边界隔离168小时；每段均含正负样本，阈值只由验证集选择。设备编号、时间、故障状态与未来标签不进入模型特征。

固定锚点2026-10-21，现有模型实际训练结果：

| 指标 | 结果 |
|---|---:|
| 模型参考分与SHAP解释 | 24台设备均生成 |
| 测试窗口 | 6,645 |
| 故障前正窗口 | 1,008 |
| 正常负窗口 | 5,637 |
| TP / FP / FN / TN | 603 / 185 / 405 / 5,452 |
| 预警命中率（精确率） | 76.52% |
| 故障前窗口发现率（召回率） | 59.82% |
| 正常窗口误报率 | 3.28% |
| F1 | 0.6715 |
| 独立测试故障 | 24次 |
| 提前发现的独立故障 | 23次 |
| 平均提前量 | 121.39小时，仅统计提前发现的事件 |

精确率=TP/(TP+FP)，召回率=TP/(TP+FN)，误报率=FP/(FP+TN)，F1=2TP/(2TP+FP+FN)。独立故障按故障开始事件计数，不能将1,008个正窗口视作1,008次故障。

平均提前量逐事件使用真实时间差复算，不固定填成168小时。未发现的事件保留在事件检出率分母中，不将其提前量记为0。

## 数据包与复算

`outputs/model-validation-v1/FactoryPulse-model-validation-v1.zip`包含：

- dataset.json：项目8张业务表，JSON格式供留存和复查；不是Excel上传格式。
- fault-events.json：模拟故障发生与修复记录。
- test-replay.json：逐测试窗口的预测、预警结果和已观察标签。
- evaluation.json：模型指标、24台评分与解释、时间分区和独立复算结果。
- manifest.json：随机种子、锚点、来源及文件SHA-256摘要。

运行`scripts/build-model-validation-dataset.py --anchor 2026-10-21`可重新生成。测试会从逐窗口预警结果重新计算混淆矩阵及指标，并从故障发生时间和预警时间复算提前量。

同一批模拟设备按时间留出，只检验模拟分布内的未来表现，不能证明新企业、新设备或真实现场泛化。样本更多也不会自动使风险分数成为故障概率。
